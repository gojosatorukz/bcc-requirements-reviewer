# Повтор запроса создания платежа

Учебная спецификация платёжного адаптера. Рассматривается один логический платёж, один аккаунт компании и один региональный endpoint. Ключ находится в пределах срока действия.

## Правила

- PAY-1. Для создания платежа адаптер отправляет POST с заголовком `idempotency-key`. При повторе того же запроса используется тот же ключ.
- PAY-2. Если HTTP-ответ не получен из-за тайм-аута, адаптер может повторить запрос с тем же ключом. Если первая попытка уже обработана, повтор возвращает её ответ без повторного выполнения платежа.
- PAY-3. Если вторая попытка с тем же ключом поступает, пока первая ещё обрабатывается, API возвращает для дубликата HTTP 409 или 422 с кодом 704.
- PAY-4. Если адаптер получил HTTP-ответ об ошибке и в нём `transient-error: true`, он может повторить запрос позже с тем же ключом. Если заголовок отсутствует или имеет значение `false`, адаптер не повторяет запрос.

## Приёмочные наблюдения

| Исходные условия | Ожидаемое поведение |
| --- | --- |
| Первый запрос обработан, но адаптер получил тайм-аут вместо ответа. Адаптер повторяет запрос с тем же ключом. | Возвращается ответ первой попытки. Платёж не выполняется повторно. |
| Два запроса с одним ключом поступили одновременно, второй принят до завершения первого. | Для второго запроса возвращается HTTP 409 или 422 с кодом 704. |
| На POST поступил HTTP-ответ об ошибке с `transient-error: false`. | Адаптер не повторяет запрос. |
