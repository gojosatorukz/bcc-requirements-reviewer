# Защита «Разбор ТЗ»

## Что открыть до показа

Из корня репозитория запустите `python3 -m reviewer.serve`. Откройте рабочее место, автономный отчёт исходного прогона и перепроверку ошибочной редакции в трёх вкладках. Во второй вкладке раскройте «Две цитаты из ТЗ», в третьей найдите «Замечание открыто». Для устного рассказа и показа всех сумм достаточно самой презентации. [Рабочее место](http://127.0.0.1:8765/) · [Исходный расчёт](../runs/bcc-executable/review.html#execution-D-01) · [Перепроверка редакции](../eval/freeform-owner/runs/ready-wrong-same-month.html) · [Слайды с заметками](bcc-pitch.pptx)

## Сценарий на 90 секунд

| Когда | Что сделать | Что сказать |
| --- | --- | --- |
| 0–12 с | Открыть замечание о месяце покупки в «Согласовании». | «Я системный аналитик карточной команды. Для одной покупки на 4 000 тенге мне нужен ожидаемый результат, который QA сможет проверить. Покупка прошла через полночь между январём и февралём». |
| 12–32 с | Показать блок «Исполняемый пример», открыть строки 38 и 64 и первый шаг расчёта. | «Обе суммы начинались с нуля. Февраль получает ноль по правилу даты покупки и четыре тысячи по приёмочному примеру. Исходы расходятся в момент проведения». |
| 32–54 с | Нажать «Ответить своими словами». Ввести реплику из первого хода ниже. Для нового вызова нажать «Передать ответ агенту». | «Владелец предлагает третий счётчик. Нам ещё нужно выяснить, меняются ли вместе с ним месячные итоги». Пока модель отвечает, показать сохранённый первый ход, затем назвать три значения. |
| 54–77 с | Перейти в автономную перепроверку. Показать исходную проблему, итоговое решение и цитату из строки 38 новой редакции. | «Январь ноль, февраль ноль, переходящие четыре тысячи. Эту покупку исправили. Но следующая покупка внутри одного месяца попадёт сразу в два счётчика. QA получает второй тест, а замечание остаётся открытым». |
| 77–90 с | Вернуться к последнему слайду. | «Дайте нам две обезличенные спецификации карточного продукта и их правки. Вместе с аналитиком и QA проверим, какие замечания стоит принять и сколько времени занимает согласование». |

Первый ответ для демонстрации — «Для покупок на стыке месяцев завели отдельный счётчик „Переходящие“. Это точно». В сохранённом прогоне агент спросил, сколько после проведения этой покупки покажут **каждый** из трёх счётчиков. Полный ответ владельца распределяет сумму только в «Переходящие» на стыке месяцев и только в обычный счётчик внутри одного месяца. Ответы владельца и обе редакции подготовили для испытания. Новая формулировка вопроса может отличаться. ## Если жюри попросит другой документ

Откройте отчёт о частичном списании в гостинице. С баланса 71 900 ₸ при бронировании заблокировано 28 600 ₸, а при расчёте списано 17 400 ₸. Если остаток блокировки сохраняется, доступно 43 300 ₸. Если блокировка снимается целиком, доступно 54 500 ₸. При полном списании обе трактовки оставляют 43 300 ₸. Эти исходы можно воспроизвести локально по сохранённой программе. [Незнакомое ТЗ](../eval/executable/card-capture.md) · [Результат агента](../eval/executable/runs/hotel.json) · [Эталон и проверки](../eval/executable/protocol.md)

```sh
python3 -m reviewer.render eval/executable/runs/hotel.json /tmp/bcc-hotel.html
python3 -m eval.executable.hotel_probes
```

В гостиничном испытании независимо сверены 1 799 наборов сумм для одной модели учёта. Отдельно посмотрите случаи с разницей в один тенге и с равными итогами. [Протокол пересчёта](../eval/executable/runs/hotel-probes.json)
