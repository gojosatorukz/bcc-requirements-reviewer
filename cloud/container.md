# Полное рабочее место в Docker

Образ запускает тот же Python-агент и тот же интерфейс, что и команда `python -m reviewer.serve`. Внутри есть сохранённый официальный прогон, исполняемые примеры, диалог с владельцем и его перепроверка.

## Открыть на своём компьютере

В чистом клоне соберите версию с идентификатором коммита для паспорта будущих прогонов. Для локальной сборки с незакоммиченными изменениями опустите `--build-arg`.

```sh
docker build --build-arg VCS_REF="$(git rev-parse HEAD)" -t razbor-tz:local .
docker run --rm --init -p 127.0.0.1:8765:8765 razbor-tz:local python -m cloud.runtime
```

Откройте [рабочее место](http://127.0.0.1:8765). Ссылка предназначена для браузера на этом компьютере. Если порт занят, используйте, например, `-p 127.0.0.1:18765:18765` и `python -m cloud.runtime --port 18765`. Проверка Host и Origin требует совпадения портов снаружи и внутри контейнера. После остановки контейнера новые временные прогоны удаляются. Если результат нужен позднее, скачайте JSON или HTML. Из HTML можно напечатать PDF средствами браузера.

Перепроверить сохранённые расчёты можно без сети и учётной записи.

```sh
docker run --rm --network none razbor-tz:local python -m reviewer.executable replay runs/bcc-jury/review.json
```

## Проверить новый документ

Для нового прогона выберите профиль в локальном файле `.env`. Docker получает значения при старте с `--env-file .env`.

| Профиль | Переменные |
| --- | --- |
| Как на публичном сайте, OpenAI Responses API | `REVIEW_PROVIDER=openai`, `REVIEW_MODEL=gpt-6.2-sol`, `OPENAI_API_KEY` от своего API-проекта |
| Локальный пример из `.env.example`, Gemini API | `REVIEW_PROVIDER=gemini`, `REVIEW_MODEL=gemini-3.5-flash-lite`, собственный `GEMINI_API_KEY` |

В прямом профиле OpenAI плата за обращения зависит от тарифа и использованных токенов. API-ключ нужен владельцу сервиса или локальной установки. Посетитель публичной страницы может загрузить документ без ключа.

```sh
docker run --rm --init --env-file .env -p 127.0.0.1:8765:8765 razbor-tz:local python -m cloud.runtime
```

### Профиль Astra

Понадобится собственный доступ к модели. Следующая команда принимает личный ключ OpenAI из переменной окружения в вашей оболочке через стандартный ввод. Codex хранит его в отдельном Docker-томе. Копировать авторизацию с другого компьютера не нужно.

```sh
printenv OPENAI_API_KEY | docker run --rm -i -v razbor-codex-auth:/home/reviewer/.codex razbor-tz:local codex login --with-api-key
docker run --rm -v razbor-codex-auth:/home/reviewer/.codex razbor-tz:local codex login status
docker run --rm --init -p 127.0.0.1:8765:8765 -v razbor-codex-auth:/home/reviewer/.codex razbor-tz:local python -m cloud.runtime
```

В рабочем месте загрузите документ, дождитесь окончания проверки и скачайте отчёт. По умолчанию запрашивается `gpt-6.2-astra`. Если в вашем API-проекте доступна другая совместимая модель, передайте её имя в переменной `REVIEW_MODEL` контейнера. Использование ключа расходует средства его владельца. Для удаления авторизации выполните `codex logout` в контейнере с тем же томом.

CLI можно запустить отдельно. Поместите тестовый документ в `./input/requirements.md`. Каталог `./output` должен разрешать запись пользователю контейнера с UID 10001.

```sh
mkdir -p output
docker run --rm --init -v razbor-codex-auth:/home/reviewer/.codex \
  -v "$PWD/input:/input:ro" -v "$PWD/output:/output" \
  razbor-tz:local python -m reviewer /input/requirements.md /output/review.json
```

Штатный сервер по умолчанию слушает loopback внутри контейнера. Модуль `cloud.runtime` включают только для локального проброса порта, показанного выше. Для сайта с отдельной сессией для каждого посетителя используйте облачную точку входа `python -m cloud.public` за HTTPS-прокси. [Публикация для жюри](hosting.md)

### Резерв Gemini через OpenAI Responses API

В собственном развёртывании с основным Gemini укажите `REVIEW_PROVIDER=gemini`, модель Gemini и её ключ. Если при исчерпании квоты нужен платный резерв OpenAI, задайте три переменные ниже. `OPENAI_API_KEY` храните как секрет сервиса. После применения настроек на главной странице рядом с загрузкой ТЗ появится имя резервной модели. До первой отправки посетитель видит, кто сможет получить документ. Для локального запуска подходят те же переменные в исключённом из Git файле `.env`.

| Переменная | Значение |
| --- | --- |
| `REVIEW_FALLBACK_PROVIDER` | `openai` |
| `REVIEW_FALLBACK_MODEL` | `gpt-6.2-sol` либо доступная в API-проекте GPT-модель с поддержкой Responses, structured outputs и reasoning effort `medium` |
| `OPENAI_API_KEY` | Проектный API-ключ с доступом к выбранной модели |

При исчерпании квоты Gemini полное ревью перезапускается через OpenAI. Этапы, цитаты и исполняемые примеры проходят те же проверки. В паспорте доступны исходная модель, причина переключения, провайдер итогового прогона и идентификаторы моделей из ответов API. Число вызовов и токены относятся к итоговому анализу. До переключения Gemini мог выполнить часть работы. Если после лимита Gemini резерв также исчерпал квоту, исчерпал кредиты или не завершил ревью, сайт выдаёт частичный отчёт по локальным правилам и указывает исход попытки резерва. Ошибка основного Gemini, отличная от лимита, завершает запуск с ошибкой.

Для прямого режима задайте `REVIEW_PROVIDER=openai`, `REVIEW_MODEL=gpt-6.2-sol` и серверный секрет `OPENAI_API_KEY`. Лимит OpenAI или исчерпание его кредитов на сайте даёт частичный отчёт в JSON и HTML, в том числе после промежуточных успешных этапов. В CLI для этого нужен флаг `--partial-on-quota`. Прочие ошибки прямого провайдера завершают проверку с ошибкой. Чтобы отключить резерв в профиле Gemini, очистите `REVIEW_FALLBACK_MODEL` и `REVIEW_FALLBACK_PROVIDER`. В прямом профиле OpenAI сервер использует `OPENAI_API_KEY` для каждого модельного этапа.

При сбое полного прогона ищите `review_stage_error` в журнале контейнера. Поле `stage` указывает этап, `code` уточняет причину. Например, `output_limit` означает обрыв JSON по длине, а `evidence_validation` означает, что модель за три попытки не обосновала вывод по источнику. Если отклонена гипотеза дополнительной проверки границы, запись `review_stage_skipped` отмечает её в журнале. Агент продолжает независимый расчёт и общую проверку, а отклонённые попытки сохраняет в паспорте.

Каждый этап OpenAI по умолчанию выполняется последовательно. Выходной бюджет включает рассуждения и JSON. Для запроса до 10 000 символов включительно агент запрашивает до 4096 токенов, до 35 000 символов — 8192, для более длинного — 16 384. Необязательный `OPENAI_MAX_OUTPUT_TOKENS` задаёт дополнительный потолок от 1024 до 16 384 на запрос. Слишком маленького значения может не хватить для полного JSON. Для временного ограничения запросов агент выполняет один повтор, учитывая `Retry-After` до 30 секунд. При исчерпании кредитов или лимита расходов повторных запросов к этой модели нет. Фактическое списание зависит от использования токенов и тарифа проекта.
