# Одна правка, два разных вопроса

**Устранён ли конфликт?** Проверяем, стали ли совместимы правило выбора месяца и пример приёмки. **Выполнено ли решение владельца?** Проверяем, зачислена ли покупка в тот месяц, который выбрал аналитик в карточке D‑01.

В [выданном ТЗ](../../submission/requirements.md) покупка на 4 000 ₸ совершена 31 января в 23:58 и проведена 1 февраля в 00:03 по Алматы. [Базовый отчёт](../../runs/bcc-submission/review.json) связывает `first` с январём (строка 38), а `second` с февралём (строка 64). В [январской редакции](january.md) критерий приёмки меняется на январь. В [февральской редакции](february.md) правило меняется на дату проведения. Каждая копия отличается от оригинала ровно одной строкой. Выбор стороны смоделирован для эксперимента и не связан с реальным решением BCC.

[Протокол](protocol.md) зафиксирован коммитом `8712968`. Исходные файлы, SHA-256 и ожидаемые статусы указаны там же. Во всех модельных вызовах используется GPT‑6.2 Astra. Перепроверка охватывает только D‑01 и независимый конфликт D‑02 о повторном push после повышения порога.

Исторический движок увидел фактическое начисление в январе или феврале соответственно. Он подтвердил устранение исходного конфликта в обеих редакциях. При запуске у него не было отдельного решения владельца для сопоставления.

В [HTML-отчёте «выбран январь, реализован февраль»](runs/after-february-first.html) рядом видны оба вердикта. Строка 38 теперь выбирает дату проведения, то есть февраль для операции из строки 64. Это устраняет расхождение в ТЗ и одновременно нарушает зафиксированный выбор января. Два февральских запуска получили одинаковый файл и наблюдали `second`. Проверка решения дала разные ответы из-за разных записанных выборов владельца. Выбор сравнивается с наблюдением программно, а модель оценивает новую редакцию по двум возможным исходам. [Тест одинаковых аргументов модели](../../tests/test_owner_decision.py)

Хеш базы совпал во всех шести JSON. Сверены хеши редакций, снимки исходника, дословные цитаты, исходы из базового свидетельства и привязка D‑01 к изменённой строке. D‑02 остался без привязки к правке и без поля решения. Каждый из пяти модельных прогонов прошёл с одним принятым вызовом, отклонённых попыток не было. На точной копии исходника вызовов не было. Время приведено для отдельных прогонов и не оценивает типичный выигрыш или задержку.

## Как повторить

Из чистого дерева `7303504f1338`, передав абсолютные пути к базе и редакции. Для исторического теста используйте `dd9fdb7c1455` и уберите `--decision` и `--baseline-sha256`.

```sh
python3 -m reviewer.recheck "$BASE" "$REVISION" /tmp/recheck.json \
  --model gpt-6.2-astra --finding D-01 --finding D-02 \
  --decision D-01=first --baseline-sha256 9938b9c13e4bdde61157a049b5ac69985fbbfe328474c41ffbbd96003fb53706
python3 -m reviewer.render /tmp/recheck.json /tmp/recheck.html
```

Тот же случай проверен отдельно через настоящий Chrome и локальный сервер. Для D-01 в рабочем месте зафиксировали январь, загрузили февральскую редакцию, получили «устранено» у замечания и «противоречит решению» у выбора владельца. Перепроверка через Astra заняла 18,11 с.
