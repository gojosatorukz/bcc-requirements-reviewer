# Округление комиссии на двух оплатах

Это дополнительное синтетическое ТЗ проверяет применимость агента за пределами расчёта месячных счётчиков и остатков по карте. Существуют две точки округления и один наблюдаемый показатель, который становится доступен магазину при закрытии дня. Запись сделана до первого запуска на этом входе. [Документ](merchant-fee.md)

Входные суммы в тиынах — 399 и 401. Ставка 1,25 % равна 1/80. В алгоритме эквайера 399 // 80 даёт 4 тиына, а 401 // 80 даёт 5. В выписку нужно записать 9 тиынов. Другой алгоритм сначала складывает суммы и начисляет комиссию сразу на 800 тиынов, поэтому поле выписки должно содержать 10 тиынов. Внешний результат появляется при закрытии дня. Рассчитанные промежуточные величины могут отличаться раньше, если агент назовёт их внутренними начислениями. До закрытия дня выдавать их за сумму в выписке нельзя.

Сохраним первую оплату 399 тиынов и проверим вторую граничащую сумму 400. Тогда первое правило даёт 4 + 5 = 9, второе — 799 // 80 = 9. Следующий тиын на второй оплате приводит к разнице в один тиын. Для двух оплат по 400 тиынов результат по обоим правилам равен 10. Повторные значения нужно получить той же программой с новыми входами. Если агент остановился на верном обнаружении и не смог воспроизвести этот расчёт, укажем обе части результата отдельно.
