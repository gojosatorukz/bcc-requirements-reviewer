# Публичные решения BCC-HUB × MNU Agent Challenge 2026

Срез на 27 ноября 2026 года по времени Астаны. Публичный код показывает связь проекта с заданием, если автор её указал или в дереве виден официальный кейс. Факт отправки, допуска и места по этим данным установить нельзя. Организатор принимает материалы до 23:59 27 ноября, отбор заявлен на 28 ноября — 1 декабря. [Страница хакатона](https://bcchubagents.mnu.kz/) · [Задание и входной документ, коммит 928c1aa](https://github.com/BCC-HUB/ai-requirements-validator-task/tree/928c1aa364265426105b69ba7a3444eac11b22db)

В таблицах 35 репозиториев с прямой ссылкой на событие или задание, 15 со связью по кейсу либо косвенным признакам и 9 внешних аналогов. Некоторые позиции — форки или незавершённые заготовки. Среди проектов с нулём звёзд есть работающий код, например у обоих прямых форков организатора, KIKER, PROSVET и RequirementLab. Ближайший аналог нашего протокола на полной конкурсной спецификации — **PROSVET**. В более узком календарном сценарии ту же парную проверку публикует **KIKER**. Снимки закреплены ниже по коммитам. Доступные отчёты и метрики авторов проверялись как артефакты. Чужие агенты и тесты не запускались.

## Как воспроизвести поиск

GitHub Repository Search использовался с `is:public`, без фильтра по звёздам. Основные запросы передаются целиком в `q`:

```text
"BCC-HUB" in:readme is:public created:>=2026-11-18
"BCC" "MNU" in:readme is:public created:>=2026-11-01
bcc mnu in:name,description is:public
"bcchubagents.mnu.kz" in:readme is:public
"ai-requirements-validator-task" in:readme is:public
ai-requirements-validator in:name is:public fork:true
"Агент проверки требований" in:readme is:public
"Уведомление о расходах по карте" in:readme is:public
"requirements validator" is:public created:>=2026-11-20
"requirements reviewer" is:public created:>=2026-11-20
"Agent Challenge" in:name,description,readme is:public created:>=2026-11-18
"ISO/IEC/IEEE 29148" in:readme is:public created:>=2026-11-20
"requirements validation" in:readme is:public created:>=2026-11-20
"Maqsut Narikbayev" hackathon in:readme is:public created:>=2026-11-18
"талаптарды тексеру" in:readme is:public created:>=2026-11-18
"fintech hackathon" in:readme is:public created:>=2026-11-18
"bcc" in:name is:public created:2026-11-25..2026-11-27
"статическое ревью" "требований" in:readme is:public created:>=2026-11-18
"IEEE 830" "Gemini" in:readme is:public created:>=2026-11-19
```

Пример повторения первого поиска и проверки фактической сети форков:

```sh
curl -fsSG 'https://api.github.com/search/repositories' \
  --data-urlencode 'q="BCC-HUB" in:readme is:public created:>=2026-11-18' \
  --data-urlencode 'per_page=100' \
  | jq -r '.items[] | [.full_name, .stargazers_count, .fork, .description] | @tsv'
curl -fsS 'https://api.github.com/repos/BCC-HUB/ai-requirements-validator-task/forks?per_page=100' \
  | jq -r '.[] | [.full_name, .stargazers_count, .forks_count] | @tsv'
```

В REST-сети два прямых форка, **AdilPython** и **azekowka**, оба с нулём звёзд и собственным кодом. Параметр `fork:true` в поиске по имени также находит независимые репозитории. [REST-сеть форков](https://api.github.com/repos/BCC-HUB/ai-requirements-validator-task/forks?per_page=100)

Поиск по коду GitHub дополнительно проверял фразы «Февральский счётчик вырос», «На карту приходится максимум один такой push», «Уведомление о расходах по карте», `BCC-HUB x MNU`, `bcchubagents.mnu.kz` и имя официального репозитория. Поиск по конкретным фразам нашёл `zhneo/goodgame` и привёл к исходникам проверки редакций PROSVET. Веб-поиск по домену GitHub с названием события, именем задания и фразой из кейса в основном вернул организатора и посторонние мероприятия. Для аналогов выполнялись запросы `requirements smell detector`, `requirements ambiguity checker`, `requirements contradiction detection` по именам/описаниям и `requirements quality tool ISO 29148` по README.

Для каждого кандидата выбиралась публичная ветка по умолчанию, читались README, дерево и релевантные входы, файлы кода и отчёты. Ссылки фиксируют SHA из комментария GitHub ZIP. Чтобы повторить проверку файла, открыть URL с SHA или прочитать архив `https://codeload.github.com/<owner>/<repo>/zip/<sha>`. Для нескольких копий официальный вход дополнительно сверялся по SHA‑256 `e7dae55e5453a250d93e335f5ff9c7f775f4457ccddd333f4a67e47b20d74381` (KIKER, Saqta Labs, ReqAudit kubectl-bekzhan и VllSunday, а также AbekD, L4RBIX, nurkhan0, Da0ss, Garryflop, q4erty, mirranet, ruslan-berkin, glore81, saynzz и 01danl). Индекс GitHub и содержимое отчётов, переданных организаторам отдельно, ограничивают полноту среза. Fork-связи по публичным метаданным: abylaiyess-svg → VllSunday и OralbekUrusbekov/goodgame → zhneo/goodgame. Два варианта ClarifAI имеют одинаковый файл sandbox и сходный пайплайн. Это срез репозиториев, а число команд из него не выводится.

Для презентации достаточно трёх проверяемых шагов. Показать исходный полный отчёт и два блокера. Заменить одно слово, показать хеш и единственный diff, затем открыть полный повторный отчёт с D2. На коротком независимом ТЗ показать противоположные исходы правила при снижении суммы и их совпадение после изменения условия. Связать каждый шаг с готовностью начать разработку или тестирование и сохранить ссылки на соответствующие артефакты, чтобы жюри могло повторить сверку.
