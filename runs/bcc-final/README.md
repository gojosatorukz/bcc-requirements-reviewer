Разбиение реестра учитывает несколько проверяемых утверждений в одной строке. Поэтому три строки приёмочной таблицы могут дать четыре пункта. Четырнадцать незаполненных строк организационного чек-листа отражены в карте покрытия как шаблон. Строки о параметрах запроса, полях ответа и все шесть JSON-блоков имеют записи в реестре.

## Воспроизведение

Сохранить официальный файл по указанной ссылке как `requirements.md`. Запустить из корня проекта:

```sh
python3 -m reviewer requirements.md output/review.json
python3 -m reviewer.render output/review.json output/review.html
python3 -m reviewer.render output/review.json output/review.pdf
```

Готовые HTML и PDF получены из одного сохранённого JSON. Смысловое содержание файла прогона сохранено без редакторских изменений. В последующих коммитах добавлены рендеринг, печать, ввод PDF и дополнительные проверки таблиц. Они не меняют указанную в паспорте версию модельного анализа. Для воспроизведения чтения и печати сохранённого результата модель не вызывается.

## Проверка результата

Проверены соответствие хеша входа опубликованной версии, охват непустых строк без пропусков, наличие атомов для контрактных таблиц и JSON-примеров, дословность цитат, разрешение всех 22 предварительных локальных замечаний и всех шести кандидатов в конфликт. HTML имеет 853 внутренних перехода, все ведут к существующим адресам. Реестр и замечания также присутствуют в печатной версии.

Контроль покрытия устанавливает, что каждый блок обработан. Интерпретации и серьёзность замечаний требуют оценки владельца документа. Например, D-05 зависит от того, означает ли «вернуть прежнее состояние» передачу старых значений клиенту. Указание владельцу согласовать состав тела ответа сохраняет практический смысл при обеих трактовках.
