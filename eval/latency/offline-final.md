# Показ при исчерпанной квоте модели

**Репетиция прошла в настоящем Chrome.** Сохранённый официальный отчёт можно открыть, проверить цитаты, пересчитать пример на других входах и показать результат перепроверки. До отправки нового вопроса помощнице счётчик обращений к CLI оставался на нуле. [Отчёт](../../runs/bcc-release/review.html) · [Исходный JSON](../../runs/bcc-release/review.json)

## Сценарий на финале

1. Запустить локальное рабочее место командой `python3 -m reviewer.serve`. Открыть демо, затем карточку D-15 в полном отчёте. Проверены переходы к строкам 155, 180, 185, 190, 192 и 197. Строка 190 показывает явную метку 404 под заголовком 403. Скачанный JSON совпал с архивом по SHA-256.
2. В D-01 нажать «Изменить входные данные». При исходном нуле покупка на стыке месяцев даёт за февраль 0 / 4 000 ₸. Задать начальный февральский счётчик 100 ₸ и нажать «Пересчитать». Получается 100 / 4 100 ₸. Выбрать «Контроль» и снова пересчитать. При обеих датах в феврале результат 4 000 / 4 000 ₸. Оба пересчёта выполнены локальными правилами.
3. В разделе «Ответ владельца» выбрать D-01, открыть сохранённый диалог и его перепроверку. В диалоге видны предложенный третий вариант и довопрос о распределении покупки между тремя счётчиками. Перепроверка показывает отдельно два результата. Прежнее противоречие устранено, а новая редакция всё ещё расходится с решением владельца. Замечание открыто. [Диалог](../../runs/bcc-release/owner/dialogue.html) · [Перепроверка](../../runs/bcc-release/owner/wrong-revision.html)

## Что произойдёт при новом запросе

На изолированном порту в `PATH` сервера находился только тестовый `codex`. Каждый его запуск увеличивал счётчик и немедленно возвращал `quota_exhausted`. Вызовов внешней модели не было. При просмотре отчёта, переходах по цитатам, двух пересчётах и открытии архивного диалога/перепроверки Chrome обращался только к localhost.

| Действие | Наблюдаемый результат |
| --- | --- |
| Новый вопрос помощнице | Одна отклонённая попытка, HTTP 429 и сообщение «Достигнут лимит запросов к модели. Откройте сохранённый пример или повторите запрос позже.» Вопрос остался в поле, нового ответа в истории не появилось. |
| Полная проверка нового Markdown | Прогон завершился ошибкой с той же подсказкой. Заглушка зафиксировала две отклонённые попытки этого прогона. |
| Новая перепроверка изменённого ТЗ | Прогон завершился ошибкой с той же подсказкой, одна отклонённая попытка. |
| Возврат к официальному демо | Карточка D-02 по-прежнему показала 1 / 2 push. D-15 и выгрузка исходного JSON остались доступны. |

До исправления буквальный ответ `quota_exhausted` показывался как общий сбой провайдера (502). На версии `752bd34` тот же сценарий возвращает приведённую выше подсказку. SHA-256 отчёта до и после проверки — `460c1efdc009a25f22d4f14f331a3734622b71678099def151e0cb0e076fae2b`. Репетиция моделирует отказ внешнего провайдера при работающем локальном сервере. [Обработка ошибки провайдера](https://github.com/gojosatorukz/bcc-requirements-reviewer/commit/752bd34)
