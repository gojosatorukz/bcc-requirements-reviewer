# Какой моделью строить исполняемый пример

**Решение на 27 ноября 2026 года, 03:10:33 UTC (08:10:33 в Астане)**. Оставляем Astra для построения примера. В единственном полностью завершённом парном раунде оба маршрута правильно решили пять основных задач. Медиана отношений времени Sol/Astra составила **1,294** при заранее установленном пороге **≤ 0,80**. Для смены маршрута нужны два полных успешных раунда с интервалом в час и обратным порядком. Предыдущие две попытки оказались неполными. Числа описывают построение программы и независимый аудит для уже найденного замечания. В обоих маршрутах аудитором выступала Astra. Для двух push-программ и гостиничного примера Sol потребовалось по три модельных обращения с учётом исправления. Для остальных маршрутов хватило двух. В этом раунде Sol занял больше времени на каждом из пяти основных случаев. С включением шестой пары медиана составила 1,305. Сравнение охватывает именно эти замечания и нагрузку провайдера во время измерения. Из него нельзя вывести стоимость коммерческого API или скорость полного ревью нового ТЗ.

**Предел вывода по SDK.** Настоящий TigerBeetle при `Flags = 0` после первого вызова показал `pending=0, posted=10` и вернул `pending_transfer_not_pending` при втором вызове. С явно включённым `Pending` первый вызов показал `pending=10, posted=0`, второй завершился `created`. Вторая ветвь программ в таблице моделирует необходимую предпосылку намерения из комментария. В наблюдаемом сервере 10 единиц ожидают проводки только в исправленной редакции с другим флагом. По этой причине SDK учитывается отдельно. Это отсутствие ответа. Эти попытки исключены из вычисления медиан и подсчёта смысловых отказов. [Первый неполный раунд](runs/round-1/) · [Второй неполный раунд](runs/round-2/)

Команда повторной проверки из корня проекта

```bash
python3 eval/witness-routing/audit.py
```

Проверка работает офлайн. Она сверяет SHA входного отчёта, исходные строки, фактическую модель и аудитора, заново исполняет программы и контроли, проверяет метку и единицы наблюдаемого поля и выводит парные времена. Продолжительность считается по времени от старта построения до получения проверенного результата. Полное перестроение отчёта проверено отдельно.
