# Отчёт по официальному ТЗ для жюри

Покупку на 4 000 ₸ совершили 31 января и провели 1 февраля. По Ф-2 она увеличит январский счётчик, по критерию приёмки из строки 64 эта же сумма попадёт в февральский. Для этой покупки агент показывает оба счётчика, задаёт вопрос владельцу и проверяет его решение на следующей редакции документа. [Открыть пример с расчётом](review.html#execution-D-01) · [PDF](review.pdf) · [JSON агента](review.json) · [Исходное ТЗ организаторов](https://github.com/BCC-HUB/ai-requirements-validator-task/blob/928c1aa364265426105b69ba7a3444eac11b22db/docs/requirements.md)

## Почему для подачи выбран этот прогон

Оба прогона использовали один оригинал, GPT-6.2 Astra и шесть параллельных задач. В каждом было ноль восстановленных попыток. Таблица показывает объём работы и её результат на этом документе. [Предыдущий отчёт](../bcc-release/review.json) · [Сверка обеих версий](../../eval/official-coverage/item-quality.md)

| Показатель | Предыдущий | Выбранный |
| --- | ---: | ---: |
| Время | 410,60 с | 312,05 с |
| Обращения к модели | 17 | 19 |
| Входные / выходные токены | 297 167 / 35 092 | 334 393 / 34 988 |
| Строки документа / выделенные блоки | 198 / 138 | 198 / 138 |
| Требования / приёмочные примеры / элементы контракта | 92 / 4 / 8 | 87 / 4 / 17 |
| Всего записей реестра | 104 | 108 |
| Проверка отдельных пунктов | Статус, вывод, цитата | Те же поля и 174 именованные оценки с цитатой для 108 из 108 пунктов |
| Нарушения / открытые вопросы | 5 / 12 | 6 / 10 |
| Критические замечания | 2 | 2 |
| Совпадение с внутренней матрицей команды | 12 тем и 14 ситуаций | 12 тем и 14 ситуаций |

Разница во времени между этими двумя измерениями составила 98,55 с. Для оценки типичной задержки и доли пропущенных замечаний нужны повторы на независимых документах. При сравнении реестров следует учитывать разную детализацию одних и тех же исходных строк.

### Сопоставление с критериями жюри

У каждого критерия вес 25%. Ниже записано, что можно проверить самостоятельно. Баллы выставляет жюри. [Рубрика организаторов](https://bcchubagents.mnu.kz/)

| Критерий | Что изменилось и где проверить |
| --- | --- |
| Уточнение требований | Оба отчёта спрашивают про месяц покупки, повторный push и обязательность `result` и `enabled` для четырёх статусов ошибки. В выбранном прогоне частичный ответ владельца приводит к довопросу о числах на трёх счётчиках. У предыдущего отчёта есть преимущество — отдельный вопрос о связи возврата с исходной покупкой. В новом правило учёта возврата есть в R-019, отдельная карточка вопроса отсутствует. [Вопрос к контракту API](review.html#D-15) · [Диалог](owner/dialogue.html) |
| Архитектура | На каждом из 108 пунктов можно открыть критерий, вывод и исходную цитату. Два исполняемых примера воспроизводятся по JSON обычной командой. Их контрольные сценарии дают одинаковые результаты для обеих трактовок. Для чтения настройки в D-06 агент фиксирует, что предусмотренной в документе информации недостаточно для вычисления. [Реестр и сценарии](review.html) |
| Ценность и качество продукта | Предыдущий D-01 показывает итог февраля. Новый D-01 показывает, куда делись деньги в каждом из двух месяцев. По D-02 результат для одной карты — 1 либо 2 push. В пяти сценариях QA три результата уже определены, два ожидают решения владельца. Испытание с учебным ответом владельца показало, что ошибочный двойной учёт в новой редакции оставляет замечание открытым. Замера с сотрудниками банка пока нет. [Сценарии QA](review.html#qa-scenarios) · [Итог перепроверки](owner/wrong-revision.html) |
| Презентация и защита | На первой странице PDF одновременно видны оба блокера и возможные результаты. Цепочку «получить ответ → уточнить правило → проверить правку» можно пройти по сохранённым материалам без доступа к модели. ## Воспроизведение

Скачайте исходное ТЗ по ссылке выше как `requirements.md`. Из корня проекта выполните команды. Первая пересчитывает исходы и контрольные примеры по сохранённому JSON. Вторая сверяет восемь файлов с контрольными суммами, привязку ответов владельца и перепроверки к этому прогону, затем собирает ZIP.

```sh
python3 -m reviewer.executable replay runs/bcc-jury/review.json --source requirements.md
python3 presentation/package_submission.py requirements.md bcc-materials.zip
```
