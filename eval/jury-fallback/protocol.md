# Публичная проверка запасной модели

Организатор выездного шахматного турнира готовит ведомость багажа. Кладовщику нужно знать, сколько ящиков вынести к машине для 13 шахматных часов. Файлы синтетические, созданы для этого испытания. Проверяющий получает по одному Markdown-файлу. Ожидаемые ответы и этот протокол остаются вне модельного запроса.

| Вход | SHA-256 исходных байтов | Что должен различить агент |
|---|---|---|
| `packing-v1.md` | `ba9c14901486dd53c305c269519e73f5af4b8789e99f30bae1af61f8fbe51aab` | Строка 4 даёт 4 ящика для 13 часов. В строке 11 указано 3. Нужны обе цитаты и вопрос владельцу о количестве, вместимости или правиле упаковки. Для 12 часов обе стороны дают 3. |
| `packing-v2.md` | `1c9d4d27cee39eaaa979df6701b23fa9baa6ab43bae0a5b919fee52a648a09d1` | Изменена одна ячейка строки 11. Теперь требуется 4 ящика. Замечание о несовместимости строк 4 и 11 должно исчезнуть, согласованная строка 10 остаётся контрольной. |

Для первого испытания загрузите каждый файл через публичную форму обычной полной проверки в отдельном новом сеансе. Сохраните выданные сервером JSON и HTML. Для результата запишите фактический провайдер, модель, версию, число новых вызовов. Чистый контроль получает отдельный прогон. Готовый пример, импорт старого отчёта и структурная проверка этого результата не дают.

Ту же проверку через Chrome выполняет `node eval/jury-fallback/site.mjs packing-v1 output/site-v1`. Второй запуск с `packing-v2` открывает независимый сеанс. Нужен Playwright с Chromium или Chrome. Для установленной отдельно копии можно задать `PLAYWRIGHT_PACKAGE` и `CHROME_BINARY`. Успешный запуск сохраняет отданные сайтом файлы. При отказе сервера сценарий проверяет доступность проверки структуры, записывает сообщение с формы и завершается с кодом 2.

Из корня репозитория можно проверить каждую пару файлов следующей командой. Параметр `--provider` сверяет провайдера в паспорте. При независимом повторе без автоматического переключения его можно опустить.

```sh
python3 -m eval.jury-fallback.audit packing-v1 output/v1.json output/v1.html
python3 -m eval.jury-fallback.audit packing-v2 output/v2.json output/v2.html
```

Аудит проверяет полноту структуры JSON, исходные байты ТЗ, внутренние ссылки и вопросы в HTML. Отдельно показывает попадание по размеченной паре, пропуск и ложные конфликты на согласованных парах. Остальные критические находки выводятся для ручной сверки. Самостоятельное вычисление количества учитывается только для воспроизводимой программы с подходящими исходными данными и единицами. Текстовые объяснения доступны для проверки отдельно. Два родственных коротких документа не устанавливают общую точность модели на банковских ТЗ.
