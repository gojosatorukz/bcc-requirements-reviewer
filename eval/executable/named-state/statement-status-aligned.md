# Статус подписания банковской выписки

Клиент заказал электронную выписку и через мобильное приложение следит за подписанием. Счёт и операции по нему остаются без изменений. Действия оператора и доставка уведомлений находятся за рамками сервиса.

## Контракт чтения

Для зарегистрированного заказа GET /statements/{id} возвращает HTTP 200 и JSON с полем status. Наблюдаемое значение — одна строка из справочника QUEUED, AWAITING_SIGNATURE, MANUAL_REVIEW, READY, REJECTED. У статусов нет числовых кодов и порядка.
Сразу после регистрации status равен QUEUED. Первый запрос к сервису подписи запускается позже. До его результата приложение показывает QUEUED.
Сервис подписи возвращает ровно один результат первой попытки: подписано, сертификат отклонён или сервис временно недоступен. Заказ существует во всех трёх случаях.

## Публикация статуса

Если первая попытка завершилась результатом «сервис временно недоступен», GET возвращает status=AWAITING_SIGNATURE до следующей попытки.
При подписании GET возвращает status=READY. При отклонении сертификата GET возвращает status=REJECTED. Следующая попытка в рассматриваемом сценарии ещё не запускалась.

## Приёмка мобильного клиента

| Начало | Результат первой попытки | Статус в первом последующем GET |
| --- | --- | --- |
| Заказ зарегистрирован | подписано | READY |
| Заказ зарегистрирован | сертификат отклонён | REJECTED |
| Заказ зарегистрирован | сервис временно недоступен | AWAITING_SIGNATURE |
