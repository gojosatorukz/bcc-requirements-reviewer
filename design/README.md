# Рабочее место аналитика и сценарий защиты

Открыть [макет](review-study.html) в браузере. Доступны выбор календарной политики, предпросмотр её последствий и возврат к открытому вопросу. Ссылки ведут к конкретным строкам опубликованной версии кейса. Макет использует ручной пример для проверки дизайна. Для продукта те же представления должны заполняться из результата прогона.

## Что видит человек

**На входе** аналитик выбирает документ. Пустое состояние говорит, какие форматы доступны, куда пойдут данные и где появится отчёт. При запуске он видит фактические этапы чтения и сверки. Процент прогресса уместен только при известном знаменателе.

**В очереди решений** сверху находятся вопросы, которые меняют ожидаемое поведение клиента. Для каждого видны краткая ситуация, владелец решения и статус. Сортировать по влиянию на разработку и приёмку, затем по числу затронутых правил. Число одинаковых упоминаний в документе не повышает приоритет.

**На карточке** взгляд проходит от покупки к двум исходам и к выбору владельца. Дата, время и сумма расположены в одном ряду. Два фрагмента стоят рядом с объяснениями, как каждый из них меняет результат. Короткая фраза над вариантами объясняет, кто может принять решение. На узком экране источники идут перед выбором. Выбранное состояние доступно с клавиатуры. Статусы передаются текстом и цветом.

**После ответа** аналитик видит изменение конкретного требования и приёмочного примера. При ответе «зависит от типа операции» полноценный продукт должен позволять собственный вариант и запросить недостающее условие. Макет исследует только два описанных исхода и откладывание решения. Автоматическая запись в исходный документ требует отдельного явного действия. Повторный прогон на копии показывает, какая находка закрылась, какие сохранились и что проверено частично.

**Перед передачей QA** доступны полный отчёт, открытые вопросы, тестовые сценарии и паспорт прогона. Принятый человеком выбор относится к конкретной версии. Повторное открытие статического отчёта должно работать без учётной записи, провайдера модели и сервера команды.

## Показ за 100 секунд

| Время | Что происходит на экране | Какой тезис можно защитить |
|---|---|---|
| 0–12 с | Показать дату покупки, дату проведения и задать залу один вопрос о месяце. | Один кейс понятен аналитикам и техническому жюри. |
| 12–24 с | Упомянуть реальный спор Barclaycard с корректным разделением £100 кешбэка и £75 компенсации. | Выбор даты уже имел наблюдаемое значение для клиента. [Решение омбудсмена](https://www.financial-ombudsman.org.uk/decision/DRN-3711674.pdf) |
| 24–45 с | Открыть карточку из настоящего прогона, обе ссылки, расчёт исходов. Перейти в строку приёмки. | Жюри самостоятельно проверяет основания. |
| 45–67 с | Выбрать политику, увидеть приёмочный сценарий, затем показать явно подписанный прогон исправленной копии. | Согласованное решение меняет результат проверки. Исходный файл организаторов доступен отдельно. |
| 67–83 с | Открыть вторую проблему про новый порог и контроль с обычным переводом. | Агент способен заметить конфликт в истории событий и признать согласованные правила. |
| 83–100 с | Показать отчёт, команду повторного запуска и измеренные результаты на отложенных примерах вместе с ошибками. | У жюри остаются воспроизводимый артефакт и границы применимости. |

## Вопросы на защите

- **«Почему не задать этот вопрос напрямую модели?»** Открыть наш сравнительный прогон с тем же входом и моделью. Признать случаи, где базовый запрос оказался достаточен. Показать конкретную пользу проверяющего этапа и цену его запуска.
- **«Что вы на самом деле доказали математически?»** Показать, что выбранные трактовки дают разные наблюдаемые исходы на одном входе. Затем открыть текст, на котором построены трактовки. Семантическая интерпретация требует отдельного ревью.
- **«Сколько денег сэкономит банк?»** Привести только измеренные время ревью и качество при наличии соответствующего теста. Реальное дело омбудсмена показывает возможное последствие, оценка ROI требует банковской статистики.
- **«Могу ли я дать вам другое ТЗ?»** Дать жюри CLI или форму нового запуска. При неверном формате, плохом извлечении или недоступности провайдера показать причину и состояние незавершённой проверки.
- **«Кто выбирает правильное правило?»** Аналитик направляет вопрос владельцу продукта. Агент показывает последствия вариантов и помогает QA проверить согласованное решение.
