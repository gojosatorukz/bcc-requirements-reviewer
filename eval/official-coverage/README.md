# Ручная проверка официального отчёта BCC

На двух прямых противоречиях агент указал правильные пары строк и посчитал разные наблюдаемые исходы. Из 12 тем ручной матрицы восемь разобраны по существу, три частично и одна пропущена. Из 14 контрольных ситуаций двенадцать разобраны полностью, две частично. Восемь из шестнадцати карточек отчёта — открытые вопросы. Эти числа описывают один сохранённый запуск и внутреннюю разметку проекта. У жюри свои критерии и веса. [Ручная матрица](../../docs/case-matrix.md) · [Официальный исходник, 198 строк](https://github.com/BCC-HUB/ai-requirements-validator-task/blob/928c1aa364265426105b69ba7a3444eac11b22db/docs/requirements.md) · [Проверенный отчёт](../../runs/bcc-executable/review.json)

Сверены версия движка `e35f768538ef`, SHA-256 отчёта `44f8b82673d93b908c525df94eb3f3891641e29b78efdb6ee99d3ec1501d4b21` и SHA-256 входа `e7dae55e5453a250d93e335f5ff9c7f775f4457ccddd333f4a67e47b20d74381`. Сначала прочитаны исходные условия, затем все 16 итоговых карточек, относящиеся к ним записи реестра, выводы для разработки и QA и две сохранённые программы. В таблицах `D1` — номер темы матрицы, `D-01` — номер карточки отчёта, `R-001` — строка его реестра. «Полно» означает, что по материалам отчёта можно ответить на заявленную проверку либо адресовать владельцу конкретный нерешённый вопрос. Для «частично» указано, какой вывод ещё пришлось делать проверяющему.

## Что может исказить оценку

Из 16 итоговых карточек две описывают критические поведенческие конфликты, пять — существенные нарушения, одна — редакционное нарушение и восемь — существенные открытые вопросы. В промежуточном массиве шесть гипотез. В частности, предполагаемое столкновение чтения и записи стало обоснованным замечанием об отсутствующем контракте чтения. Суммировать гипотезы с итоговыми карточками было бы двойным счётом. Обе вычисленные критические пары, 38/64 и 39/40, подтверждаются первоисточником. Ложного критического конфликта при этой сверке не обнаружено.

Самая спорная оценка значимости у D-11. В ТЗ одновременно указан заголовок и отсутствует тело, а пример запроса опускает заголовок. Полезно спросить, обязателен ли он. Из этого материала нельзя заключить, что соединение клиента с сервером нарушится. В QA-рекомендации R-077 также стоит проверить предположение об отклонении текстовой записи `01`. Строка 144 задаёт целое, один знак и значение 0 или 1. Способ нормализации query-строки явно не определён. R-077 остаётся предлагаемым тестом.

Кроме двух прямых конфликтов, отчёт выявляет основанный на тексте пробел D-04. На экране должен быть месячный итог по карте (29), в цепочке расчёта участвует сервис расходов (26), а поле amount в описанном ответе означает порог (156). Путь получения месячного итога приложением требует уточнения. Это полезный результат вне прямого перечня D1–D12. Ему не присваивался дополнительный балл в счётчике покрытия.

Оценка выполнена вручную одним рецензентом по известному официальному примеру. Матрица создана внутри проекта, внешней разметки организаторов для этих 26 тем нет в сравниваемых материалах. Числа выше нельзя переносить на точность модели, другие банковские ТЗ, скорость работы аналитика или шансы выхода в финал.
