Все пять страниц проверены по изображениям. На строках 73 и 75 PDF перенос дал пробел в выражениях «продукты/ системы» и «бизнес- процесса». На строке 94 фрагмент CURL представлен как `demo- 42`, в Markdown стоит `demo-42`. Перед копированием запроса следует сверить значение с исходником.

До изменения разметчик видел в этом PDF 0 из 6 примеров JSON. После изменения он проверяет синтаксис самостоятельных объектов и массивов в моноширинном тексте, сохраняя исходные координаты строк. Пример должен помещаться на одной странице и не превышать 64 строк. Пропорциональный шрифт, разрыв на границе страниц, незакрытая скобка и тела внутри табличных ячеек могут остаться обычным текстом. Для сканов нужен OCR.

## Где остановился первый запуск

На версии `9f447da` все семь групп строк прошли локальную проверку. Стадия сценариев исчерпала три попытки и остановилась на HTTP 403. На странице 5 есть строка «403. Unsuccessful — Forbidden», но валидатор терял заголовки «Ответ» и «Статусы» после печати. Из семи объявленных кодов он находил ноль. Полный отчёт из этой попытки не был записан.

Версия `9ee7b7d` распознаёт печатные заголовки с HTTP reason phrase и учитывает соседние данные. Обычный номер заказа, сумма и произвольное трёхзначное число в JSON не дают основания приписывать серверу HTTP-статус. Два ранее сохранённых отчёта по тарифному PDF прошли повторную проверку по исходным байтам и координатам страниц.

## Воспроизведение

В окружении с `pdfplumber` эти команды проверяют файл и создают HTML-отчёт. Выполняйте их из корня репозитория.

```sh
python3 eval/pdf-official/audit.py
python3 -m reviewer.executable replay eval/pdf-official/review.json --source eval/pdf-official/requirements.pdf
python3 -m reviewer.render eval/pdf-official/review.json /tmp/bcc-pdf-report.html
```

Чтобы сравнить ячейки и JSON-значения с Markdown, передайте его путь команде `python3 eval/pdf-official/audit.py --markdown requirements.md`. SHA-256 исходного Markdown — `e7dae55e5453a250d93e335f5ff9c7f775f4457ccddd333f4a67e47b20d74381`. SHA-256 проверенного PDF — `6e54b30a9e09e4120db789983561d066ac820a86387c6aa7b8a10f17e9506e9c`.

Для подготовки PDF использовались Marked 17.0.5 и Chrome 158.0.8127.38, для чтения — pdfplumber 0.11.9. [Скрипт печати](print_source.py) принимает пути к Markdown и новому PDF. Он передаёт семантический HTML в Chrome, поэтому Markdown-ограждения вокруг примеров на бумаге отсутствуют. Повторная печать может дать другой SHA из-за метаданных времени и версии браузера. Для воспроизведения сохранённого прогона используйте вложенный PDF.
