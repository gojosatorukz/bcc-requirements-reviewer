## Как устроена наша публикация

GitHub хранит исходный код и историю изменений. При выбранном вручную деплое Render забирает нужный коммит и по Dockerfile собирает **образ** с Python, приложением и сохранённым примером. Render запускает копию образа на своём сервере и выдаёт сайту адрес на `onrender.com`. Когда аналитик загружает своё ТЗ, Python-процесс на Render обращается напрямую в OpenAI Responses API с моделью GPT-6.2 Sol и готовит отчёт. Вызовы модели оплачивает API-проект владельца сервиса. Ноутбук автора при этом может быть выключен. [Сборка из Dockerfile](https://render.com/docs/docker) · [Адрес веб-сервиса](https://render.com/docs/web-services)

Свой **домен** — отдельная покупка. Уже имеющийся домен можно подключить через поддомен, например `review.example.kz`. Регистрация домена даёт право пользоваться именем на оплаченный срок. Исполнение Python-кода и обращения к модели обеспечивает выбранный сервис. [Домены и DNS на Render](https://render.com/docs/custom-domains)

В хакатонной версии у каждого браузера своя временная папка с документами и отчётами. Для возвращения к работе аналитик скачивает JSON и позже открывает его вновь. Для пилота в банке с историей согласований понадобятся учётные записи, постоянное хранилище документов и база для решений владельцев. Платный сервер имеет смысл, когда нужны сохранность между перезапусками и доступ без ожидания пробуждения. [Ограничения временного диска и бесплатного сервиса](https://render.com/docs/free)

## Опубликовать выбранную версию

1. В Render выберите **New → Blueprint** и предоставьте доступ к закрытому репозиторию проекта. На экране предварительного просмотра должен быть один Web Service с тарифом **Free**. Конфигурация находится в [render.yaml](../render.yaml).
2. В поле `OPENAI_API_KEY` укажите секрет проекта OpenAI с доступом к GPT-6.2 Sol. Профиль Blueprint задаёт `REVIEW_PROVIDER=openai` и `REVIEW_MODEL=gpt-6.2-sol`. Для существующего сервиса сверьте те же значения в **Environment**, где хранится ключ. Примените конфигурацию, когда будете готовы опубликовать сайт. Сборка использует Dockerfile из ветки `main`. Последующие версии можно выпускать вручную через **Manual Deploy**. [Как Render обрабатывает Blueprint](https://render.com/docs/blueprint-spec)
3. Скопируйте выданную Render HTTPS-ссылку со страницы сервиса. Сервер получает адрес через `RENDER_EXTERNAL_HOSTNAME` и порт через `PORT`. При подключении собственного домена задайте `PUBLIC_ORIGIN`, например `https://review.example.kz`, без завершающего слеша. [Переменные окружения Render](https://render.com/docs/environment-variables)
4. Со второго устройства откройте сайт, введите собственное ТЗ, дождитесь результата и скачайте отчёт. В другом браузере тот же персональный отчёт должен быть недоступен. Отдельно откройте сохранённый пример и PDF. У полного отчёта по новому файлу проверьте в JSON `run.provider = openai-responses`, `run.model = gpt-6.2-sol` и SHA-256 входа. Паспорт сохранённого банковского примера указывает GPT-6.2 Astra.

## Основной провайдер и квота

В прямом профиле GPT-6.2 Sol получает новое ТЗ сразу. При лимите модели или исчерпании кредитов полная проверка нового документа переходит к частичному отчёту по локальным правилам. В таком результате видны тип отчёта и причина. Доступ к готовому банковскому примеру, его PDF и повтору сохранённых расчётов сохраняется при любом остатке квоты. Ошибки доступа к модели и ключу требуют исправить настройки сервиса.

Профиль с основным Gemini можно развернуть отдельно. Для него доступны опциональные резервы OpenAI или Cloudflare при исчерпании квоты Gemini. Полное ревью в таком случае запускается заново, а в паспорте появляется `run.fallback_from`. [Настройки профилей](container.md) · [Архив испытания резерва](../eval/jury-fallback/protocol.md)

## Как посетитель пользуется сайтом

Откройте [публичное рабочее место](https://razbor-tz.onrender.com/) или перейдите сразу к [отчёту по официальному ТЗ](https://razbor-tz.onrender.com/reports/demo/review.html). Оба адреса доступны в новой браузерной сессии. На бесплатном Render после простоя запуск контейнера может задержать открытие первой страницы.

Ключ указывает владелец сервиса. Посетитель выбирает **Вставить текст** или **Загрузить файл**, запускает ревью и видит этап проверки. Готовый HTML открывается с цитатами и вопросами. **Печать / сохранить PDF** делает копию для коллеги. JSON позволяет вернуться к разбору после новой сессии.

При исчерпании квоты частичный отчёт может указать противоречащие исходы на границе, пропущенное обязательное поле в примере ответа или повреждённый JSON. У найденных проблем есть вопрос и номера исходных строк. Такой отчёт нельзя выбрать базой для проверки новой редакции.

Кнопка **Проверить структуру без ИИ** принимает тот же текст или файл. Сервер извлекает текст и таблицы и проверяет синтаксис распознанных JSON-примеров. Он возвращает результат сразу и освобождает данные этого запроса. Смысловые конфликты проверяет отдельное полное ревью. Готовые отчёты и примеры расчётов можно открыть при любом остатке квоты.

Для проверки опубликованного релиза запустите `python3 cloud/verify_public.py` из копии проекта или выберите **Actions → Check the public jury site → Run workflow**. Из нового HTTPS-сеанса проверяются контрольные суммы трёх файлов официального отчёта, сохранённый пример Gemini и пара «сломанный JSON → исправленный JSON». Запросы загрузки содержат небольшой синтетический пример, заданный в самой проверке.

Доступ к новым документам и ответам привязан к cookie конкретного браузера. Участники видят общий сохранённый пример и собственные результаты. Эта версия очищает неактивные сессии примерно через два часа, а перезапуск удаляет все временные прогоны. Сохраняйте документы до этого момента. Одновременно сервер обслуживает до двух проверок или обращений к помощнице/владельцу. На экземпляр предусмотрено до 40 запросов запуска или вопросов за скользящий час. Один полный анализ сам может вызвать модель несколько раз. Ограничения запросов и кредитов API-проекта OpenAI действуют отдельно. В пилоте используйте материалы, которые разрешено передавать выбранному провайдеру.
