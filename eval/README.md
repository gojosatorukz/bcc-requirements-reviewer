# Проверка контрольных сценариев

Исходная пара — официальное ТЗ BCC и его копия с одной правкой. Ф-2 относит проведённую покупку к месяцу совершения. В строке 64 примера меняется только «Февральский» на «Январский». D1 должен исчезнуть из критических нарушений, D2 про повторный push должен сохраниться.

```sh
python3 -m eval.make_bcc_aligned /path/requirements.md /tmp/bcc-aligned.md
python3 -m reviewer /tmp/bcc-aligned.md /tmp/bcc-aligned.json
python3 -m eval.score_review bcc-aligned /tmp/bcc-aligned.json
```

Движок получает только входное ТЗ. Скрипт оценки работает уже с сохранённым отчётом и не обращается к модели.

```sh
python3 -m eval.score_review bcc runs/bcc-final/review.json
python3 -m eval.score_review payment eval/holdout/runs/payment-approval.json
python3 -m eval.score_review payment-aligned eval/holdout/runs/payment-approval-aligned.json
```

На независимой паре проверяется конфликт при уменьшении суммы и его отсутствие после согласования правил. Для полного отчёта скрипт проверяет категорию «нарушение» и приоритет «критический». В исправленном ТЗ BCC скрипт отмечает D1, если тот сохранился как нарушение с любым приоритетом. Для полного отчёта по платёжной паре лишний критический вывод приводит к расхождению. В исторических отчётах платёжной пары доступен только список поведенческих конфликтов. Поля `stage` и `priority_available` указывают, что проверено. [Ожидания для платёжной пары](holdout/expected.md)

Совпадение проверяется по дословным цитатам из двух контрольных строк и содержательным фрагментам этих цитат. В выводе остаются целые находки, кандидаты, источники и сценарии. Проверьте вручную, что в сценарии выполняются условия обеих сторон, исходы действительно несовместимы и ответ владельца разрешает конфликт. Поле `manual_review_required` отмечает случаи, когда нужно дополнительно проверить ссылки на обе контрольные строки с иными цитатами или критические находки без привязки к контрольным сценариям. Итог охватывает только четыре фиксированных входа, включая оба отрицательных контроля. Код возврата 0 означает прохождение структурных проверок, 1 — расхождение, 2 — ошибку входа.
