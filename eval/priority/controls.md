# Протокол повторных полных прогонов

До запуска зафиксированы семь контролей. Номера D-ID, порядок перечисления и формулировки могут меняться. При сопоставлении проверяются исходные строки, условия и фактический смысл замечания. Для каждого входа выполняются три независимых полных запуска без контрольных точек и без передачи предыдущих результатов модели.

| Документ | Проверяемый дефект | Ожидаемый приоритет |
|---|---|---|
| Официальное ТЗ | Месяц покупки против месяца проведения в приёмке | Критический |
| Официальное ТЗ | Второй push после повышения порога | Критический |
| Официальное ТЗ | Клиент использует GET для замены настройки | Существенный |
| Официальное ТЗ | Недостающий контракт чтения настроек | Существенный |
| Резерв продавца | При равенстве суммы резерв одновременно высвобождается и остаётся удержанным | Критический |
| Резерв продавца | Клиент использует GET для записи формата сводки | Существенный |
| Резерв продавца | Две разные записи имени одного автора в паспорте | Редакционный |

Для резерва в 18 000 ₸ расчёт на 17 000 ₸ даёт согласованный результат HELD. Этот пример отдельно проверяется на ложное срабатывание. Пропуски и дубли считаются отдельно от расхождения приоритетов. Дополнительные находки вне таблицы сопоставляются по смыслу после запусков.
