# Перенос проверки на правила повторного платежа

Русскоязычный учебный кейс основан на действующей публичной документации Adyen об идемпотентности. В согласованном ТЗ отдельно описаны дубликат до завершения первой попытки, повтор после тайм-аута без HTTP-ответа и полученная ошибка с `transient-error: false`. В экспериментальной копии изменена только ожидаемая реакция адаптера в строке 18. Противоречие внесено в учебный кейс. [Adyen API idempotency](https://docs.adyen.com/development-resources/api-idempotency/) · [Протокол и точные разделы источника](protocol.md)

Входы, SHA-256 и ожидания зафиксированы до первого запуска в коммите `91a77ae961ce3aea90b27ed596f3c04c6526fe5e`. Полные прогоны выполнены из чистого detached-клона на этом коммите через Codex CLI и `gpt-6.2-astra`. Для каждого холодного прогона выделен свой новый каталог контрольных точек. Сохранённые стадии, эталон и ссылка на документацию Adyen к модельному вводу не добавлялись.

## Результаты

| Вход | Длительность | Новые вызовы / восстановленные стадии | Кандидаты в конфликт | Критические нарушения | Дословные ссылки |
| --- | ---: | ---: | ---: | ---: | ---: |
| [Согласованный](runs/source.json) | 92,92 с | 3 / 0 | 0 | 0 | 41 / 41 |
| [С мутацией](runs/mutated.json) | 105,98 с | 3 / 0 | 1 | 1 | 50 / 50 |

Во всех шести холодных стадиях первый ответ был принят. «Холодный» здесь означает свежие локальные контрольные точки. Паспорт согласованного прогона показывает 10 880 входных токенов, обработанных с помощью кэша провайдера. Полные счётчики вызовов и токенов сохранены в JSON.

- **Согласованный вход.** Реестр отдельно передал исход дубликата до завершения первого запроса, исход повтора после тайм-аута и запрет повтора после полученной ошибки с `false`. Критических нарушений нет. Единственная находка — существенный открытый вопрос о минимальной паузе при уже разрешённом повторе после `transient-error: true`. Это отдельное решение реализации за пределами контрольной развилки.
- **Мутация.** Обе приведённые цитаты дословны. Строка 10 запрещает повтор при `false`, строка 18 требует второй POST с тем же ключом. В обеих ветвях ответ об ошибке уже получен, ключ действителен, аккаунт и endpoint совпадают. Исходы «нет второго POST» и «второй POST позже» несовместимы. Вопрос владельцу разрешает ту же развилку, а итоговая находка явно ограничивает эффект отправкой лишнего запроса.
- **Предел формулировки модели.** В сценарии модель подставила HTTP 503 с `transient-error: false`. Локальное ТЗ не задаёт код для этого случая. В документации Adyen конкретный 503/703 при недоступности хранилища идемпотентности помечается как временная ошибка. Поэтому связку 503 с `false` нельзя засчитывать как проверенное поведение API. Для доказательства в учебном ТЗ достаточно полученного HTTP-ответа об ошибке с `false`, без предположения о коде. [Adyen, Designing for resilience](https://docs.adyen.com/development-resources/api-idempotency/#designing-for-resilience)
- **Контроли согласия.** Строки 10 и 18 в мутированной версии несовместимы на всех входах строки 18. Вручную сверены два независимых контроля. Строки 8 и 16 возвращают ответ уже обработанной попытки без повторного платежа. Строки 9 и 17 возвращают дубликату до завершения 409/422 с кодом 704.

Для обоих отчётов сверены SHA-256 исходников, встроенный текст и каждая пара номера строки и цитаты во всех вложенных разделах. Оба JSON успешно прошли штатный рендеринг HTML.

## Возобновление согласованного прогона

Затем тот же полный CLI в том же клоне повторно получил согласованное ТЗ и использовал его сохранённые контрольные точки. Длительность — **0,02 с**, новых вызовов — **0**, `current_usage` — `{}`, восстановлены все три стадии. Поля отчёта вне паспорта, в том числе реестр и итоговые находки, совпали. Исторические счётчики оригинального прогона сохранены в `usage`. [Компактное подтверждение](runs/warm-source.json)

## Повторение

Из чистого клона зафиксированного коммита:

```sh
payment_run_dir=$(mktemp -d)
python3 -m reviewer eval/public-payments/source.md "$payment_run_dir/source.json" \
  --model gpt-6.2-astra --checkpoint-dir "$payment_run_dir/source-checkpoint"
python3 -m reviewer eval/public-payments/mutated.md "$payment_run_dir/mutated.json" \
  --model gpt-6.2-astra --checkpoint-dir "$payment_run_dir/mutated-checkpoint"
python3 -m reviewer eval/public-payments/source.md "$payment_run_dir/source-warm.json" \
  --model gpt-6.2-astra --checkpoint-dir "$payment_run_dir/source-checkpoint"
```

Это одна согласованная адаптация и одна мутация, по одному новому полному прогону на версию. Эксперимент проверяет различение трёх узких состояний повторного запроса и один конфликт приёмки. Он не измеряет полноту или стабильность на других документах. Возобновление отдельно проверяет локальное повторное использование стадий.
