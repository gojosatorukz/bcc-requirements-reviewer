# Отмена поручения на выплату

Команда расчётов обрабатывает поручения в тенге. Оператор может отменить ещё не исполненное поручение. Все часы местные; границей служит момент приёма запроса шлюзом. Приём повторного запроса с тем же ключом возвращает первоначальный результат. Поручение в состоянии PAID больше не изменяется.

## Операционный регламент

CLR-1. Для поручения в состоянии QUEUED при отсутствии ручной блокировки шлюз принимает отмену до 16:00:00 включительно. Немедленный результат — состояние CANCELLED, перечисления денег не происходит.
CLR-2. Позже 16:00:00 шлюз отклоняет отмену, поручение остаётся QUEUED. При активной ручной блокировке отмена всегда отклоняется независимо от времени.

## Примеры приёмки

| До операции | Момент первого запроса | После операции |
|---|---|---|
| QUEUED, блокировки нет | 15:59:59 | CANCELLED, перевод отсутствует |
| QUEUED, блокировки нет | 16:00:00 | Отказ в отмене, поручение остаётся QUEUED |
| QUEUED, блокировки нет | 16:00:01 | Отказ в отмене, поручение остаётся QUEUED |
| QUEUED, активна блокировка | 15:58:00 | Отказ в отмене, поручение остаётся QUEUED |

## Контракт ответа

API-1. Клиент присылает POST /orders/{id}/cancel. Для принятой отмены шлюз отвечает HTTP 200. Тело — один JSON-объект с полем state типа string. При отказе шлюз возвращает HTTP 409 и текущее состояние поручения. Сервер отдаёт только один результат на запрос.

Пример тела ответа при успешной отмене:

```json
{
  "state": "CANCELLED",
}
```
