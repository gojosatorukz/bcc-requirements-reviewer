# Проверка области действия на настоящей спецификации TigerBeetle

TigerBeetle — продукт для учёта финансовых транзакций. При частичном проведении отложенного перевода имеют значение сумма и версия клиента. Это позволяет проверить ошибку, которая обходится дорого аналитику: две редакции протокола дают разные ответы, хотя к одной операции применима ровно одна из них. [Документация продукта](https://docs.tigerbeetle.com/coding/two-phase-transfers/)

[Вход](post-pending.md) содержит без изменений первые 48 строк публичного [исходного Markdown на коммите `0aeb306`](https://github.com/tigerbeetle/tigerbeetle/blob/0aeb306561365e21b97775c729bfc439f6c16d72/docs/coding/two-phase-transfers.md#L1-L48), до конца описания исторического варианта частичного проведения. Хеш всего исходника — `a7b006e9e7866d30b8cfa46e81a9e0b425d657a143304260676246320d7e3f20`. Хеш 48 строк — `d795152a745d3d1674d28ae5ebc7548015c92f4743a17435efbd8d8e9b29def0`. Исходная лицензия сохранена [отдельно](LICENSE.txt).

До первого прогона зафиксировали отрицательный контроль. Если зарезервировано 100 единиц, а на проведение передан ноль, в текущем правиле частичного проведения будет проведено 0. В явно обозначенном старом клиенте (< 0.16.0) ноль означал полное проведение, то есть 100. Режим задаётся версией клиента из строки 40. Конфликт с одинаковыми условиями для одной и той же версии здесь не подтверждён. Сумма 40 на том же резерве даёт 40 по обоим описаниям. Порядок выполнения положительных инструкций не заменяет проверку области действия.

Передаём только оригинальный Markdown через штатный полноформатный режим агента. Сверяем финальные нарушения, текстовые кандидаты и исполняемые примеры по целевой паре строк 30–33 и 40–46. Если агент приписал две несовместимые нормы одной версии, фиксируем ложное срабатывание даже при корректной арифметике. Другие замечания в укороченном отрывке рассматриваем отдельно. Подтверждение касается этой пары правил и области применимости.

В [сквозном прогоне](../runs/ledger.json) первый проход предположил два конфликта для клиента 0.15.0. Заключительное ревью сослалось на строку 40 и отклонило оба. Для нулевой суммы агент восстановил 100 для старого клиента и 0 для текущего. Для положительной суммы 40 получил одинаковые результаты в обеих версиях. Проверка сохранила четыре замечания о полноте переданного отрывка, в том числе о деталях отмены и истечения резерва, которые раскрываются дальше в полном документе. Исполняемых конфликтов агент не подтвердил. Привязка поведения к версии отдельно подтверждена в [официальных примечаниях к релизу](https://docs.tigerbeetle.com/coding/api-changes/#zero-amount-transfers).
