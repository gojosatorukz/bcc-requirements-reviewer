# Когда один пример допускает две программы

Отрицательный случай взят из полного прогона BCC. В D-09 авторы спецификации потребовали чтение настройки и описали запись с новым значением. Проверка документа не установила, что один конкретный вызов с новым `amount` одновременно предназначен для чтения. Цель повторной проверки на тех же выводах — сохранить вопрос о контракте чтения, снять вывод о двух вычислимых исходах и оставить обе настоящие коллизии о месяце и push. [Исходный модельный прогон](../stability/recovered/official.json)

На положительном учебном контроле обе части независимо описывают именно повторный POST одного клиента к одной версии сервера. Различается только наблюдаемый HTTP-код. Ожидаем 200 и 204 при повторной отправке, 202 при первой отправке с обеих сторон. Изменение одной ячейки на 200 должно снять исходный конфликт. В сценарии исторического SDK проверяем, что отсутствие явного исхода у одной из сторон не превращается в два фактических состояния сервера.
