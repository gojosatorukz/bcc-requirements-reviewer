## Что увидит аналитик

На стыке месяцев расчёты D-01 дали 0 и 4 000 ₸. Контроль дал 4 000 и 4 000 ₸. В D-02 при изменении порога результат расходится (1 и 2 push), на контроле обе стороны дают 1 и 1. [Исполняемые примеры и исходные строки](review.html)

У первого сохранения и восстановления после прерванной отправки нужен ответ владельца. Для повторного пересечения неизменного порога после возврата, границы в один тиын и двух разных карт уже можно написать тесты. Каждая карточка содержит начальное состояние, действие, наблюдение и дословные цитаты. [Пять сценариев QA](review.html#qa-scenarios) · [Перенос на кабельный цех и отрицательный контроль](../../eval/lifecycle/README.md)

Для этой редакции заново получены [два ответа владельца](owner/dialogue.html) и [перепроверка ошибочной правки](owner/wrong-revision.html). Полный протокол связывает каждый ответ с исходным вопросом и хешем этого отчёта. [Сверка 26 тем](../../eval/official-coverage/release.md) · [Демонстрация](../../presentation/live-demo.md)

Внутренняя сверка исходного JSON дала 25 из 26 полных попаданий. В D-13 агент спрашивает про обязательность `amount` и `enabled`. В HTML и PDF дополнительно вычисляется [сводка полей по каждому примеру ответа](review.html#response-fields). Она показывает, где отсутствует `result`, и даёт вопрос для сверки с нормативной схемой.

## Повторить расчёт по оригиналу

```sh
python3 -m reviewer.executable replay runs/bcc-release/review.json --source requirements.md
```

## Собрать комплект по фиксированным файлам

```sh
python3 presentation/package_submission.py requirements.md bcc-materials.zip
```

Команда сверяет семь сдаваемых файлов с [контрольными суммами](materials.json), проверяет привязку обоих ходов владельца и перепроверки к исходному JSON, а затем создаёт ZIP. В него входят оригинал ТЗ, JSON, HTML, PDF, презентация, видео и адрес репозитория. Студенческий билет участник прикрепляет отдельно в форму организаторов.
