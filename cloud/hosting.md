В репозитории есть конфигурация для одного экземпляра Render Free. Обычный push в GitHub сохраняет версию приложения. Создание сервиса и первая публикация происходят после подтверждения в Render.

## Как устроена наша публикация

GitHub хранит исходный код и историю изменений. При выбранном вручную деплое Render забирает нужный коммит и по Dockerfile собирает **образ** с Python, приложением и сохранённым примером. Render запускает копию образа на своём сервере и выдаёт сайту адрес на `onrender.com`. Когда аналитик загружает своё ТЗ, Python-процесс на Render обращается к Gemini и готовит отчёт. Ноутбук автора при этом может быть выключен. [Сборка из Dockerfile](https://render.com/docs/docker) · [Адрес веб-сервиса](https://render.com/docs/web-services)

Свой **домен** — отдельная покупка. Уже имеющийся домен можно подключить через поддомен, например `review.example.kz`. Регистрация домена даёт право пользоваться именем на оплаченный срок. Исполнение Python-кода и обращения к модели обеспечивает выбранный сервис. [Домены и DNS на Render](https://render.com/docs/custom-domains)

В хакатонной версии у каждого браузера своя временная папка с документами и отчётами. Для возвращения к работе аналитик скачивает JSON и позже открывает его вновь. Для пилота в банке с историей согласований понадобятся учётные записи, постоянное хранилище документов и база для решений владельцев. Платный сервер имеет смысл, когда нужны сохранность между перезапусками и доступ без ожидания пробуждения. [Ограничения временного диска и бесплатного сервиса](https://render.com/docs/free)

## Опубликовать выбранную версию

1. В Render выберите **New → Blueprint** и предоставьте доступ к закрытому репозиторию проекта. На экране предварительного просмотра должен быть один Web Service с тарифом **Free**. Конфигурация находится в [render.yaml](../render.yaml).
2. Для `GEMINI_API_KEY` задайте ключ своего проекта Google AI Studio с доступной бесплатной квотой. Примените конфигурацию, когда будете готовы опубликовать сайт. Сборка использует Dockerfile из ветки `main`. Последующие версии можно выпускать вручную через **Manual Deploy**. [Как Render обрабатывает Blueprint](https://render.com/docs/blueprint-spec)
3. Скопируйте выданную Render HTTPS-ссылку со страницы сервиса. Сервер получает адрес через `RENDER_EXTERNAL_HOSTNAME` и порт через `PORT`. При подключении собственного домена задайте `PUBLIC_ORIGIN`, например `https://review.example.kz`, без завершающего слеша. [Переменные окружения Render](https://render.com/docs/environment-variables)
4. Со второго устройства откройте сайт, введите собственное ТЗ, дождитесь результата и скачайте отчёт. В другом браузере тот же персональный отчёт должен быть недоступен. Отдельно откройте сохранённый пример и PDF. После успешной проверки добавьте реальную ссылку в README и материалы жюри.

## Резервная модель

На публичном сайте до подачи используется только Gemini. Для собственного развёртывания резерв для новых полных ревью и перепроверки исправленного документа включается в **Environment** сервиса Render. Основной провайдер остаётся `REVIEW_PROVIDER=gemini`. Добавьте три переменные и примените настройки к новому экземпляру сервиса.

| Переменная | Значение |
|---|---|
| `REVIEW_FALLBACK_MODEL` | `@cf/openai/gpt-oss-120b` |
| `CLOUDFLARE_ACCOUNT_ID` | Идентификатор выбранного аккаунта Cloudflare |
| `CLOUDFLARE_API_TOKEN` | Секретный токен шаблона Workers AI с Workers AI Read/Edit только для этого аккаунта. Сохраните его в Render. |

Перед загрузкой форма указывает, что при исчерпании квоты Gemini документ получит Cloudflare. При HTTP 429 агент повторяет все этапы через резерв. В полном JSON поле `run.provider` принимает значение `cloudflare-workers-ai`, а `run.fallback_from` показывает исходную модель и причину. Для проверки загрузите незнакомый документ и затем исправленную версию. [Протокол и исходные ТЗ](../eval/jury-fallback/protocol.md)

На Workers Free доступно 10 000 вычислительных единиц (neurons) в сутки на аккаунт. Один отчёт включает несколько обращений, расход зависит от длины ТЗ и ответа. После исчерпания квоты запросы останавливаются. [Тариф Workers AI](https://developers.cloudflare.com/workers-ai/platform/pricing/) · [Настройка доступа Cloudflare](https://developers.cloudflare.com/workers-ai/get-started/rest-api/)

Чтобы отключить резерв после результатов, удалите `REVIEW_FALLBACK_MODEL`, `CLOUDFLARE_API_TOKEN` и `CLOUDFLARE_ACCOUNT_ID` из **Environment** на Render и примените изменения через **Deploy**. В разделе **API Tokens** своего аккаунта Cloudflare отзовите `razbor-tz Render fallback`. Проверьте, что публичная форма показывает только Gemini. Для отключения резерва достаточно этих действий.

## Как посетитель пользуется сайтом

Откройте [публичное рабочее место](https://razbor-tz.onrender.com/) или перейдите сразу к [отчёту по официальному ТЗ](https://razbor-tz.onrender.com/reports/demo/review.html). Оба адреса доступны в новой браузерной сессии. На бесплатном Render после простоя запуск контейнера может задержать открытие первой страницы.

Ключ указывает владелец сервиса. Посетитель выбирает **Вставить текст** или **Загрузить файл**, запускает ревью и видит этап проверки. Готовый HTML открывается с цитатами и вопросами. **Печать / сохранить PDF** делает копию для коллеги. JSON позволяет вернуться к разбору после новой сессии.

При ответе Gemini HTTP 429 на запрос полного ревью сайт завершает задание частичным отчётом. В нём есть вопросы по одинаковым входам таблицы с разными исходами, явно отложенным параметрам и повреждённым JSON-примерам. Вопросы сопровождаются номерами строк. Такой отчёт нельзя выбрать базой для проверки новой редакции.

Кнопка **Проверить структуру без ИИ** принимает тот же текст или файл. Сервер извлекает текст и таблицы и проверяет синтаксис распознанных JSON-примеров. Он возвращает результат сразу и освобождает данные этого запроса. Смысловые конфликты проверяет отдельное полное ревью. Готовые отчёты и примеры расчётов можно открыть при любом остатке квоты.

Для проверки опубликованного релиза запустите `python3 cloud/verify_public.py` из копии проекта или выберите **Actions → Check the public jury site → Run workflow**. Из нового HTTPS-сеанса проверяются контрольные суммы трёх файлов официального отчёта, сохранённый пример Gemini и пара «сломанный JSON → исправленный JSON». Запросы загрузки содержат небольшой синтетический пример, заданный в самой проверке.

Доступ к новым документам и ответам привязан к cookie конкретного браузера. Участники видят общий сохранённый пример и собственные результаты. Эта версия очищает неактивные сессии примерно через два часа, а перезапуск удаляет все временные прогоны. Сохраняйте документы до этого момента. Одновременно сервер обслуживает до двух проверок или обращений к помощнице/владельцу. На экземпляр предусмотрено до 40 запросов запуска или вопросов за скользящий час. Один полный анализ сам может вызвать модель несколько раз. Фактическая квота Gemini действует отдельно. В пилоте используйте материалы, которые разрешено передавать выбранному провайдеру.
