# От статуса к оценке качества каждого пункта

В предыдущем JSON версии `report-v1` у каждой записи есть статус, вывод и цитата. Новая версия сохраняет ещё одну или две применимые проверки с названием критерия, выводом и точным местом в ТЗ. Приёмка JSON проверяет состав полей, отсутствие дублирующих критериев, привязку хотя бы одной проверки к собственному блоку и совпадение всех цитат с исходником.

| Холодный прогон, Astra | Официальное ТЗ | ТЗ о рассрочках |
| --- | --- | --- |
| Движок | 8ab3b76dadae | 8ab3b76dadae |
| Время и вызовы | 312,05 с, 19 вызовов | 153,89 с, 6 вызовов |
| Пунктов с индивидуальными проверками | 108 из 108 | 13 из 13 |
| Записанных оценок | 174 | 22 |
| Проверяемое расхождение | У одной покупки январский счётчик получает 400 000 или 0 тиынов. У одной карты за июнь 1 или 2 push. На контролях обе стороны согласны. | Для договора № 41 очередность меняет сумму зачисления с 2 000 на 6 000 ₸. На контроле суммы совпадают. |
| Источник | [Новый JSON](criterion-bcc.json) · [Предыдущий JSON](../../runs/bcc-release/review.json) | [ТЗ](../../examples/allocation.md) · [Новый JSON](criterion-allocation.json) |

Два запуска использовали разные требования и по нулю восстановленных попыток. ТЗ о рассрочках было в проекте до этой доработки. Пара 410,60 с и 312,05 с относится к двум отдельным прогонам одного документа. Для оценки устойчивого изменения скорости нужны повторы. В новом отчёте D-06 оставляет чтение настройки открытым. Описанная операция сохраняет настройку и не даёт вычислить два доказуемых результата чтения.

## Повторить без модели

Из корня проекта с оригиналом `requirements.md`, скачанным по инструкции README:

```sh
python -m reviewer.render eval/official-coverage/criterion-bcc.json output/bcc-criteria.html
python -m reviewer.executable replay eval/official-coverage/criterion-bcc.json --source requirements.md
python -m reviewer.executable replay eval/official-coverage/criterion-allocation.json --source examples/allocation.md
```

В отдельном тесте с действующим лимитом Gemini сайт получил новый синтетический документ о выдаче датчиков. Частичный отчёт спросил, в какой из двух шкафов передать комплект и за какое время нужно подтвердить выдачу. Из чистой локальной копии без ключей проверили тот же файл через сервер проекта. Полученный JSON прошёл локальную сверку с исходником и совпал с результатом отдельного запуска CLI с лимитом Gemini.
