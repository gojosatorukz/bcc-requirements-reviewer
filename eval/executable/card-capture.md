# Доступный остаток по карте при завершении авторизации

## Участники и данные

Кассир гостиницы сначала авторизует депозит на карте гостя, а при выезде передаёт в процессинг фактическую стоимость проживания. Банк показывает гостю доступную к оплате сумму. Все суммы целые, в тенге. Комиссии, овердрафт и другие операции по счёту в этом процессе отсутствуют.

Для проверки одной операции доступный остаток равен учётному остатку за вычетом суммы, которая ещё заблокирована по её авторизации. До авторизации заблокировано ноль.

## Правила процессинга

К-1. При успешной авторизации учётный остаток не меняется, банк блокирует полную сумму авторизации.
К-2. При первом клиринге со ссылкой на эту авторизацию процессинг списывает с учётного остатка фактическую сумму. Если списана только часть авторизации, разница продолжает блокироваться до отдельного сообщения гостиницы об отмене остатка резерва. Если списана полная сумма, блокировка обнуляется.

## Контракт интеграции с витриной

В-1. Витрина получает подтверждение обработки того же первого клиринга до ответа мобильному приложению. После этого подтверждения блокировка по авторизации целиком снята, включая неиспользованную разницу при частичной сумме. Учётный остаток отражает только фактическое списание.
В-2. По запросу экран возвращает текущие учётный остаток, заблокированную сумму и доступный остаток. Источник всех трёх значений один, расчёт синхронен с процессингом.

## Приёмочный сценарий

На счёте гостя 71 900 ₸. Изначально нет незавершённых авторизаций. Сначала гостиница успешно авторизует 28 600 ₸, затем присылает первый клиринг на 17 400 ₸. Новых событий после клиринга нет. Тестировщик смотрит результат в приложении сразу после подтверждения обработки.
