# Защита «Разбор ТЗ»

Системному аналитику карточного продукта нужно согласовать с владельцем правил, в какой месяц отнести покупку. QA затем проверит и этот пример, и соседний случай, который легко пропустить после правки. [Презентация с заметками](bcc-pitch.pptx) · [Демонстрация с русской озвучкой](bcc-demo.mp4)

## Что показывает запись

В Chrome открыт официальный прогон на документе «Уведомление о расходах по карте». Съёмка интерфейса, ввод ответов и локальный пересчёт выполнены при записи. Полное ревью, два ответа модели и перепроверка редакции ранее исполнены и сохранены. В рабочем месте восстановлен подлинный первый ход из этого диалога. Ожидание модели вырезано, фрагменты сохранённого прогона подписаны. Озвучка синтезирована. SHA-256 базового JSON — `b6243ba64e7b3f120418be8464379f54b00d0f5753f8dde11873445c7edb729b`. [Базовый отчёт](../runs/bcc-release/review.json) · [Оба хода владельца](../runs/bcc-release/owner/dialogue.html) · [Перепроверка](../runs/bcc-release/owner/wrong-revision.html)

| Время в видео | Что видно |
| --- | --- |
| 0–6 с | У февральского счётчика два исхода для одной покупки — 0 и 4 000 ₸. |
| 6–11 с | В строке 38 месяц задан датой совершения. Строка 64 требует зачислить эту покупку в февраль. |
| 11–17 с | Время покупки меняется с 23:58 на 00:00. После пересчёта обе трактовки дают за февраль 4 000 ₸. |
| 17–23 с | Владелец вводит третий вариант своими словами — отдельный счётчик «Переходящие». |
| 23–30 с | Восстановлен первый ответ агента. Он уточняет суммы в январе, феврале и «Переходящих». Замечание открыто. |
| 30–38 с | В поле ответа на этот довопрос вводится полное условие для покупок на стыке и внутри месяца. |
| 38–43 с | В сохранённом диалоге видны обе исходные реплики и согласованные условия. |
| 43–52 с | В отчёте о новой редакции граничный пример исправлен. Строка 38 ошибочно учитывает покупку внутри месяца дважды. Замечание открыто. |

## Повторить на защите

Запустите из корня репозитория `python3 -m reviewer.serve`. Откройте рабочее место по адресу, который выведет команда. Рядом откройте автономный отчёт и результат проверки новой редакции. Первый экран, локальный пересчёт и просмотр сохранённой переписки работают без нового обращения к модели. Для получения нового ответа владельцу требуется настроенный провайдер. [Рабочее место](http://127.0.0.1:8765/) · [Исходный расчёт](../runs/bcc-release/review.html#execution-D-01) · [Новая редакция](../eval/freeform-owner/wrong-same-month.md)

| Когда | Действие и слова ведущего |
| --- | --- |
| 0–15 с | Откройте D-01. «Я аналитик карточной команды. Покупку сделали 31 января и провели 1 февраля. Что должен увидеть клиент в февральских расходах?» |
| 15–35 с | Раскройте «Две цитаты из ТЗ». Нажмите «Изменить входные данные» и поменяйте время покупки с −2 на 0 минут от полуночи. «Для исходной покупки получились ноль и четыре тысячи. Сдвинем только её время — теперь оба правила сходятся». |
| 35–55 с | Нажмите «Ответить своими словами». Для показа без ожидания откройте «Посмотреть сохранённый пример без модели» и «Прочитать диалог». Прочтите довопрос про три счётчика. Владелец уточняет, что на стыке месяцев меняются только «Переходящие», а внутри месяца — только обычный счётчик. |
| 55–75 с | Откройте перепроверку. Сначала покажите исходное расхождение со статусом «устранено». Затем покажите второе условие и строку 38 изменённого ТЗ. «Покупка на стыке исправлена. Теперь QA знает, какой второй пример нужен для закрытия замечания». |
| 75–90 с | Откройте слайд о результатах. «В одном официальном прогоне 93 требования, 4 приёмочных примера и 9 элементов контракта. Предлагаем повторить проверку на двух обезличенных ТЗ вместе с вашей карточной командой». |

## Дословные реплики

**Первый ответ владельца.** «Для покупок на стыке месяцев завели отдельный счётчик «Переходящие». Это точно.»

**Довопрос агента.** «Если все три счётчика равны нулю, сколько должно быть за январь, за февраль и в «Переходящих» после проведения 1 февраля покупки на 4 000 ₸ от 31 января?»

**Уточнение владельца.** «Когда месяц покупки и проведения по Алматы различается, после проведения вся сумма идёт только в «Переходящие». Январь и февраль по этой покупке остаются без изменений. Если оба события в одном месяце, вся сумма идёт только в обычный счётчик этого месяца. В «Переходящие» в этом случае ноль.» [Дословные входы и ответы агента в JSON](../runs/bcc-release/owner/dialogue.json)

| Где граница между моделью и расчётом? | Модель предложила две трактовки. Интерпретатор исполнил их на общем входе. Новый ввод пересчитывается локально. В D-01 сохранён единственный наблюдаемый показатель — февральский счётчик. Строка 64 подтверждает конкретную покупку. [Программа и трасса](../runs/bcc-release/review.json) |
| Проверили ли вы документ целиком? | В реестре 106 записей. На уровне документа 6 нарушений и 10 открытых вопросов. Для D-01 и D-02 выполнены расчёты, для D-05 подтверждения исполняемого примера оказалось недостаточно. Разработка и тестирование получили статус «можно частично». В прогоне 13 новых обращений к модели, 335,15 с. Это результат одного запуска. [Полный отчёт](../runs/bcc-release/review.html) · [PDF](../runs/bcc-release/review.pdf) |
| Может ли агент принять частичный ответ или третий вариант? | После первого хода сохранена договорённость об отдельном счётчике. Автору ещё предстоит определить обычные месяцы. После второго хода новое правило готово к проверке. Для ошибочной редакции итог «открыто». [Диалог](../runs/bcc-release/owner/dialogue.html) · [Проверка двух условий](../runs/bcc-release/owner/wrong-revision.html) |
| Применимо ли это за пределами одного ТЗ? | Отдельные испытания на гостиничной авторизации и статусе банковской выписки демонстрируют денежные и символьные исходы. Точность на портфеле банка предстоит измерить. [Испытания на незнакомых документах](../eval/executable/README.md) |
| Кто будет пользоваться и зачем нужен пилот? | Системный аналитик приносит вопрос владельцу правил, QA получает согласованные примеры.
