# Фиксированный приёмочный пример

Проверяем, умеет ли агент посчитать наблюдаемый результат последовательности операций и сравнить его с явно заданным ожиданием. Если ТЗ целиком фиксирует вход, значение из приёмки применимо только к этому примеру.

1. Общий внешний набор — три исходных документа PROSVET v1.2.0. Контрольный отпечаток всего набора вместе с оракулом `a0027c3e41594639a542c829d419eee11975acc5b9b9bea3b92752cae5c72c39`. В ledger-b требуется сопоставить Л-5 и Л-6 и 500 с 100. В ledger-a и ledger-c противоречий нет. [Входы и эталон PROSVET](https://github.com/Kirirto-kun/prosvet-requirements-validator/tree/f90f5a3f994b9a8573a6e4a1fc48a9f22443934e/evals/transitions)
2. Новый [регистратор](recorder-v1.md) расходует по пути 9 и 6 Вт·ч из исходных 48. Расчёт даёт 33, а таблица для того же момента указывает 37. Правильный отчёт отделяет вычисление от буквального ожидания и задаёт вопрос владельцу. Проверяем числа, единицы и цитаты.
3. В [контроле](recorder-v2.md) изменена единственная ячейка, 37 → 33. Повторное независимое ревью должно пропустить эту пару как согласованную. Количество других открытых вопросов учитываем отдельно.

Агент получает только один файл ТЗ. Для итогового сравнения используем свежие модельные вызовы и сверяем паспорт с SHA-256 оригинала. До исправления все три внешних документа проверены локальной Astra. На ledger-b получено одно критическое замечание с верными исходами, а исполняемый пример имел статус `unsupported`. На двух контролях замечаний не было.

## Результат повторного испытания

| Вход | После изменения | Что можно перепроверить |
|---|---|---|
| ledger-a и ledger-c | Оба полных прогона завершились без замечаний | [Сводка после исправления](results/ledger-after.json) |
| ledger-b | Пересчёт доступного остатка по операциям дал 0 → 900 → 500 → 500 ₸. Строка 19 требует 100 ₸. Один открытый конфликт. | [До изменения](results/ledger-before.json) · [После](results/ledger-after.json) |
| Метеозонд | Из 48 Вт·ч вычли сначала 9, затем 6. Итог 33 Вт·ч, строка 11 требует 37. Сформирован вопрос о требуемом остатке после выключения передатчика. | [Готовый отчёт](results/recorder-v1.html#execution-D-01) · [JSON](results/recorder-v1.json) |
| Метеозонд после исправления | Агент повторно прочитал документ. Нарушений и открытых вопросов не выдал. | [Исправленный документ](recorder-v2.md) · [Полный отчёт](results/recorder-v2.html) |

На трёх общих ТЗ результаты обнаружения совпадают с опубликованными результатами PROSVET v1.2.0: один конфликт и два чистых контроля. Их трасса для ledger-b также содержит резерв и доступный остаток. Наша новая проверка фиксированной приёмки пересчитывает один выбранный показатель, отделяет буквальное ожидание и блокирует вывод при несовпадении источников. В сохранённых прогонах на три входа у нас было 15 обращений к Astra, у PROSVET — 13 к Sol. Полные конвейеры, модели и даты различаются. [Оригинальные результаты авторов](https://github.com/Kirirto-kun/prosvet-requirements-validator/blob/f90f5a3f994b9a8573a6e4a1fc48a9f22443934e/evals/transitions/results/v1.2.0.json)

Для повторной сверки чисел и строк выполните `python3 -m eval.fixed-acceptance.score eval/fixed-acceptance/recorder-v1.md eval/fixed-acceptance/results/recorder-v1.json`. Оба отчёта метеозонда получены в ходе разработки из рабочей копии с изменениями. В паспорте каждого зафиксирован отпечаток кода ядра. HTML собран из этих JSON после добавления представления расчёта.
